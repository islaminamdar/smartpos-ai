# Manager daily overview

This guide describes the candidate Operations screen. It is not yet deployed to the customer site.

Sign in to the staff counter and choose **Operations**. Managers can review activity without registering that browser as a selling counter. Select an authorized branch in **View branch**; this does not change the selling counter or its saved order. Cashier accounts do not receive management access.

Start with **Today's recorded sales**. Issued sales, credit notes and net amounts use the Dubai business date shown. Recorded cash/card amounts are the payments entered in the POS; a card figure does not confirm bank settlement. Credit notes issued today can make the net amount negative even when the original sale happened earlier.

Check **Open counters** and **Recent drawer closes**. Opening cash is the saved float, not a live drawer balance. The close comparison uses the last 30 Dubai calendar dates through the displayed read time. A negative difference means counted cash is below the recorded expectation. Missing amounts appear as **Not recorded**, and the combined difference is unavailable if any close is incomplete. Positive and negative differences can offset each other, so review the discrepancy count as well as the net amount.

Review **Unpaid orders** and **Kitchen workload**. Saved baskets are estimates, not collected sales; final offers and totals can change at checkout. Kitchen tickets and preparation batches are different counts and must not be added together. Change and stop notices need review in the kitchen screen.

**Recorded offline attention** shows only evidence already received by the server. Categories can overlap. A device may still hold bills or problems that this screen cannot see. A signed manager result on the server also does not prove that the device has received it. Use the original device and the authorized recovery workflow; this overview cannot clear records or return money.

Use **Refresh overview** for a new read. A failed refresh clearly labels any retained figures as an older snapshot and disables workflow shortcuts. Lost authorization clears the displayed branch information. The last successful refresh is always shown. Counts and totals include matching records beyond the 20 displayed rows; the screen explicitly says when rows are not shown. Excessive source volume or invalid data makes the overview unavailable rather than silently incomplete.

Workflow shortcuts open the existing reports, orders, kitchen and shift views only for the selling counter's bound branch. Another branch can be reviewed without changing that binding. These shortcuts do not close a different counter, settle an unpaid order or create a payment automatically.
